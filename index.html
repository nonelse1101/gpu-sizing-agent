LLM Inference Sizing Discovery Cheat Sheet & Architecture Guide

          
Essential customer discovery questions, roofline formulas, and device-parity rules

        

        
      


      

        

          

            
1. Model Topology & Precision

            
Total parameters (P_total) govern HBM weight storage and decode streaming bandwidth; active parameters (P_active) govern prefill FLOPs (2 × P_active FLOPs/token). Serving in FP8 (1 byte/param) halves minimum TP and doubles HBM bandwidth ceiling vs BF16.

          

          

            
2. Traffic Demand & Sequence Profile

            
Convert Tokens/Minute (M tok/min) to sustained tok/s (`Tok/s = M_tok_min * 1e6 / 60`). Long-prompt workloads (e.g. 16K in / 512 out) are Prefill compute-bound; interactive chat & reasoning (2K in / 1K out) are Decode HBM-bandwidth bound.

          

          

            
3. 8-GPU Node Alignment & G4 Flexibility

            
`a4-highgpu-8g` (B200), `a3-ultragpu-8g` (H200), and `a3-megagpu-8g` (H100) allocate in 8-GPU VM increments (`ceil(Raw_GPUs / 8) * 8`). `g4-standard` (RTX PRO 6000 Blackwell, 96 GB/GPU) supports 1, 2, 4, or 8 GPUs per VM.

          

          

            
4. Cloud TPU7x Device-Parity Rule

            
Each TPU7x chip contains 2 dies (devices), each with 1 TensorCore + 96 GB HBM3e. A 4-chip TPU7x VM = 8 devices, aligning 1:1 by device count with an 8-GPU VM (`TP=2` uses 2 devices = 1 TPU7x chip vs 2 GPUs).
